## 6. COMPLETE HOTEL BOOKING ENGINE

Build a real reservation system.

### 6.1 Booking Workflow

The complete process:

Step 1: Customer visits website.

Step 2: Customer selects Flower Inn, Petal Inn or All Hotels.

Step 3: Customer chooses check-in and checkout dates.

Step 4: Customer enters guest count and room count.

Step 5: Backend checks actual availability.

Step 6: Available room types and correct prices are displayed.

Step 7: Customer chooses room.

Step 8: System calculates the complete price.

Step 9: Customer enters guest details.

Step 10: System creates a temporary inventory reservation.

Step 11: Customer completes the supported booking/payment flow.

Step 12: Backend verifies the transaction.

Step 13: Booking is confirmed.

Step 14: Customer receives confirmation.

Step 15: Hotel dashboard receives the new booking.

Step 16: Inventory is updated atomically.

### 6.2 Booking Status

Support configurable statuses:

- Pending
- Awaiting Payment
- Confirmed
- Checked In
- Checked Out
- Cancelled
- No Show
- Expired

Record all status transitions.

A confirmed booking must never disappear when a payment provider or email service temporarily fails.

### 6.3 Prevent Double Booking

This is a critical production requirement.

Implement:

- Database transaction-based inventory reservation
- Concurrency-safe availability checks
- Atomic inventory updates
- Expiring temporary booking holds
- Idempotent booking operations
- Duplicate request protection
- Server-side final availability verification

Handle two customers trying to reserve the final room simultaneously.

Only one transaction should succeed if one room remains.

Do not rely on frontend checks for inventory consistency.

### 6.4 Date Handling

Use the hotel's configured local timezone.

Store timestamps consistently and represent hotel stay dates as calendar dates.

Check-in is inclusive and checkout is exclusive for nightly inventory.

Prevent:

- Checkout before check-in
- Invalid dates
- Zero-night stays unless explicitly supported
- Exceeding room occupancy
- Negative room inventory
- Unavailable room reservations

### 6.5 Booking Modifications

Support authorized changes to:

- Guest details
- Room type
- Stay dates
- Guest count
- Booking status

Recheck inventory and recalculate prices before confirming modifications.

Keep an audit record.

### 6.6 Booking Cancellation

Implement a configurable cancellation policy system.

Support:

- Cancellation requests
- Eligibility checks
- Refund calculation
- Admin approval where applicable
- Payment gateway refunds
- Inventory release
- Cancellation confirmation

Do not invent or hardcode final hotel cancellation policies.

### 6.7 Guest Booking

Support guest checkout without requiring an account by default.

Optionally allow customers to create accounts.

For guest booking retrieval, use secure verification, such as a time-limited link or email/phone OTP.
